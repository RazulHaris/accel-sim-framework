## 3. Cost estimate (`util/snake/s5_estimate.py`)

Method:
- **Job length** per workload: the trace's warp instructions (sum of the `insts =` lines) × the thread/warp ratio of its 100M baseline run, capped at 1B. The trace sums equal the run counts for the two workloads that finish within 100M (hotspot 512, lud 256).
- **Rate:** the slowest seconds per instruction among this machine's existing 100M runs (5–15 jobs at a time; Snake on or off).
- **Pool:** the job lengths go into a longest-first pool of 15 (16 cores).
- **Main uncertainty:** linear extrapolation (rates change across kernels). Allow ±50%.

| workload | instructions to completion | 1B job length | s per 100M (max of n runs) | est. s per 1B job |
|---|---|---|---|---|
| backprop / 65536 | 137M | 137M | 202 (3) | 277 |
| hotspot / 512_2_2___da | 93M | 93M | 134 (10) | 125 |
| hotspot / 1024_2_2___d | 374M | 374M | 133 (3) | 498 |
| lud / _i___data_51 | 194M | 194M | 256 (10) | 496 |

| histo / _i___data_de | 2183M | 1000M | 333 (9) | 3330 |

- srad_v1, histo and mri-q run into the 1B cap. The other six finish earlier: backprop 137M, hotspot 93M / 374M, lud 194M / 24M, nw 146M instructions.
- histo is the longest job (≈ 56 min); nw takes ≈ 27 min for only 146M instructions (1.5M cycles per 100M).
- **Unmeasured:**
  - memory per 1B job: 15 jobs at once on 62 GB
  - Tail 1024: every Snake table scan grows with the Tail size; no run at that size exists, and Snake's share of run time at 100M is small
  - AccelWattch is off, so there is no power-model cost
